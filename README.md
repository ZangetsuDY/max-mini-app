# MAX Mini App — все подразделения

Добавлены карточки: ВЭС, ГтЭС, ЮЭС, СЭС, ТхЭС, КС, НлЭС, КнЭС, ЮВВР, СВВР, ВВВР, ЦВВР, ОС, Волхов.

## Где вписывать chat_id

В Vercel создайте Secret Environment Variable `CHAT_IDS_JSON`.

Вставьте значение одной строкой:

```json
{"ves":"ID_ВЭС","gtes":"ID_ГтЭС","yues":"ID_ЮЭС","ses":"ID_СЭС","thes":"ID_ТхЭС","ks":"ID_КС","nles":"ID_НлЭС","knes":"ID_КнЭС","yuvvr":"ID_ЮВВР","svvr":"ID_СВВР","vvvr":"ID_ВВВР","tsvvr":"ID_ЦВВР","os":"ID_ОС","volkhov":"ID_Волхов"}
```

Если ID пока нет, оставьте пустую строку, например `"gtes":""`. На карточке будет написано, что chat_id не настроен.

Также поддерживаются отдельные переменные: `CHAT_VES`, `CHAT_GTES`, `CHAT_YUES`, `CHAT_SES`, `CHAT_THES`, `CHAT_KS`, `CHAT_NLES`, `CHAT_KNES`, `CHAT_YUVVR`, `CHAT_SVVR`, `CHAT_VVVR`, `CHAT_TSVVR`, `CHAT_OS`, `CHAT_VOLKHOV`.

Оставьте существующие `MAX_BOT_TOKEN`, `AUTH_SECRET`, `APP_USERS_JSON`.

Ваш файл `certs/Russian_Trusted_Root_CA.cer` должен остаться в проекте. Сам сертификат в архив не вложен.

После изменения Environment Variables сделайте Redeploy.


## Исправление проверки сегодняшнего дня

В этой версии диапазон запросов к MAX задаётся явно:

- начало — 00:00 по Москве за выбранное количество предыдущих дней;
- конец — текущий момент;
- сегодняшний день всегда включён.

Также время из текста оперативных сообщений интерпретируется как московское,
а не как локальное время Vercel (UTC).

Для диагностики ответ `/api/outages` теперь содержит `todayMessages`.


## Исправление от 22.09.2026

### Свежие сообщения ВЭС

Парсер теперь принимает оба используемых шаблона:

- `Аварийное отключение фидера 6-20 кВ`
- `Аварийные отключения`

Поэтому записи вида:

`Объект: В-26`
`Запись: Аварийное отключение В-26.`

теперь считаются активным аварийным отключением.

Также распознаются варианты `РПВ успешное`, `РПВ успешно`,
`АПВ успешное` и другие формы успешного восстановления.

Первый запрос к MAX теперь берёт самые свежие сообщения напрямую,
без искусственной верхней границы `from`.

### Авторизация в web.max.ru

На web.max.ru браузер может блокировать cookie Mini App как third-party cookie.
Поэтому после входа сервер также возвращает подписанный session token.
Frontend хранит его только в `sessionStorage` текущей вкладки и отправляет
в `X-App-Session`. Сервер проверяет HMAC-подпись этого токена через `AUTH_SECRET`.

Cookie оставлена как дополнительный механизм для мобильной версии.


## Расширенный парсер аварийных сообщений

Парсер теперь работает по конкретному энергообъекту, а не только по полю
`Объект`.

Поддерживаются:

- `Аварийное отключение фидера 6-20 кВ`
- `Аварийные отключения`
- `Аварийное отключение ЛЭП 35-220 кВ`
- `Аварийные события`

### Примеры состояний

Отключено:

- `Отключился ф.331-03`
- `Аварийное отключение В-26`
- `АО ф331-03`
- `В-10кВ в отключенном положении`
- `АПВ неуспешно`
- `РПВ НУ`
- `погашены потребители`
- `без напряжения`

Включено / восстановлено:

- `Включил по ТУ ...`
- `... включен от работы РЗА`
- `РПВ успешно`
- `РПВ успешное`
- `РПВ усп.`
- `АПВ успешно`
- `с успешным АПВ`
- `с усп. РПВ`
- `электроснабжение восстановлено`
- `напряжение подано`

Не закрывают аварию сами по себе:

- `подключен РИСЭ`
- `абоненты запитаны обратной трансформацией`
- `уменьшен участок`
- `выделен участок`

### Несколько фидеров в одном сообщении

Сообщение:

`аварийное отключение ф330-02,-04,-05. Успешное РПВ ф330-02,-05`

обрабатывается как:

- `ф330-02` -> включен
- `ф330-04` -> отключен
- `ф330-05` -> включен

### Канонический объект

Если поле `Объект` содержит `Рощинский РЭС`, а в записи есть `ф331-03`,
состояние хранится по `ф331-03`.

Поэтому разные фидеры одного РЭС больше не перезаписывают друг друга.

Для диагностики `/api/outages` дополнительно возвращает:

- `structuredEmergencyMessages`
- `ignoredStructuredMessages`
- `recognizedStateEvents`
